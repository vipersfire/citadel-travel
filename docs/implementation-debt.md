## Intentional production dependencies

The user explicitly requested that external keys remain optional during development. Therefore blank development credentials, simulated payments, the local notification outbox, disabled WhatsApp and local storage are **intentional behavior**.

Before enabling the corresponding production integration, the following remain necessary:

- Google OAuth client configuration and a real non-test-account sign-in/linking check.
- Hosted PostgreSQL connectivity/concurrency, R2 public-media upload and local private-file volume backup/restore checks using the user's environments.
- Xendit test-mode payload verification first; production account activation, enabled IDR channels and merchant limits before live payments.
- Resend sender/domain configuration and actual bilingual email-delivery checks.
- WhatsApp number/template approval and matching variables before enabling delivery. WhatsApp can remain disabled independently of email. Ordinary public click-to-chat links require only the real contact number.
- Turnstile, Sentry and production infrastructure credentials when those services are enabled.

These dependencies are not counted as accidental development startup blockers. Adapter code gaps and unverified behavior are listed separately above.

- Journal/editorial articles (PRD FR-09).

Supplier accounts, companion logins, public prices, instant checkout, installments, automated in-platform refunds, member visa-file uploads, native apps, loyalty and chat are explicitly outside the pilot; their absence is not debt against the agreed pilot scope.

## Recommended completion order

1. Payment/provider correctness, rate limits, shared contracts, ownership tests and PostgreSQL concurrency/schema checks.
2. Request/admin/member workflow completion and actionable operational queues.
3. Notifications/localization, file delivery, media/PDF jobs and caching.
4. Design/accessibility corrections and final approved content/assets.
5. CI, staging, performance/security UAT, monitoring and a backup restore drill.
6. Enable production integrations only after their configuration and smoke checks are complete.

Existing local verification evidence remains in [verification.md](verification.md). This register does not replace those successful checks or imply that all six documents are already complete.
